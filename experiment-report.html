1. 프로젝트 개요 & 리서치 방향

K-12 수업 프레젠테이션용 삽화를 만들기 위해 T2I 모델 후보(PixArt-Sigma, SDXL, Flux2-Klein, Z-Image, SD3.5, Sana, Lumina2, Qwen-Image, Ideogram-4)를 16GB VRAM 예산 안에서 동일 조건으로 비교하는 연구 하네스입니다. 연구개발 단계라 라이선스/파인튜닝은 의도적으로 뒤로 미루고, 지금은 "돌아가는지, 얼마나 쓰는지, 결과가 얼마나 좋은지"만 본다는 게 원칙입니다.

핵심 운영 원칙

  • 파인튜닝(LoRA)/distillation은 지금 하지 않는다 — teacher 모델 그대로 e2e가 충분히 좋으면 그걸로 끝.
  • 텍스트 렌더링 여부는 더 이상 정책적으로 막지 않는다 — 되면 좋고, 안 되면 텍스트 없는 삽화로 취급.
  • 프롬프트/모델/채점 중 무엇을 먼저 고칠지는 채점 결과가 가리키는 병목으로 판단한다.

3. 파이프라인 구조

세 축(프롬프트 리라이터 / T2I 모델 / 채점 방식)을 동시에 발전시키는 순환 구조입니다.

① 프롬프트 구축 (rewriter + style preset)  →  ② T2I 이미지 생성 (model candidates)  →  ③ 메트릭 채점 (충실도 + 스타일 + 종합)
↑____________________________ 채점 결과가 다음 라운드 개선 방향을 정함 ____________________________↓
  • ① 한국어 입력 → 영어 확장 rewriter(부정문→긍정 치환) + 목적별 style preset(S/M/L 티어) 결합
  • ② configs/models/ 후보군, 모델별 "프롬프트 방언" 차이 유의 (CLIP 키워드형 vs T5/LLM 서술형 vs negative 미지원)
  • ③ 프롬프트 충실도(VQAScore) + 스타일 반영도(CSD, custom CV) + VLM-as-judge 보조 지표, 조화평균으로 종합

6. 스타일 프리셋 v2 & Style→Object Leakage 방지

12개 프리셋 → 4개로 통합: edu-flat-v2 / playful-soft / storybook-scene / observational (+ 보류 1개 mono-minimal).

발견된 문제(style→object leakage): LLM/T5 텍스트 인코더 모델(qwen-image, lumina2 등)은 스타일 프롬프트 속 구체 명사를 오브젝트로 렌더링한다. 예: "textbook infographic style" 문구가 실제 책 오브젝트로 그려짐 — dialect 변환 confound가 아니라 원본 스타일 프리셋 자체의 문제로 확인.

R1~R9 authoring rules(등장 가능 명사 금지, 매체→시각결과 치환, 장르명 내장 명사 검사, 긍정 서술 우선 등)로 재작성. educational-flat → edu-flat-v2 파생 완료, apple/cat 재검증에서 책 오브젝트 완전 소멸, 스타일 유지 확인.

v2 4개 프리셋 R9 스모크 테스트(lumina2 + apple/cat/book) 전부 leakage 없음 → status: validated.

9. VLM Judge 신뢰성 검증 — 세 judge 삼각검증

Spec item 채점(사람 손 라벨 vs VLM judge)의 신뢰도를 Cohen's κ로 검증. 파일럿(29건) → STAGE 3 규모(125건)로 확대 재검증.

비교n전체 κclaude κchatgpt κqwen κ
사람 vs Qwen2.5-VL-7B1250.370.410.390.33
사람 vs Gemma-3-12B-4bit1250.190.34-0.040.22
사람 vs InternVL3-8B1250.330.500.440.11
결론: 세 judge 전부 κ<0.6 — spec item VLM 채점은 신뢰 불가로 확정. 표본을 29건→125건으로 늘려도 결론 불변(표본 크기 문제 아님). InternVL3-8B가 파일럿(n=29)에서 κ=0.61로 유일하게 기준을 넘겼던 것도 125건 규모에서는 κ=0.33으로 재현 안 됨.
  • 자기 계열 선호 가설(self-enhancement bias)은 3개 judge 모두에서 지지되지 않음 — qwen 소스 프롬프트에 Qwen judge가 유독 후한 패턴 없음.
  • chatgpt 소스 spec item 문구의 모호성이 judge 문제와 별개로 존재하는 것으로 보임(사람 vs Gemma-3 비교에서 chatgpt 소스 κ=-0.04, 표본 커질수록 악화).
  • 결정: spec item 채점을 모델 비교의 최종 근거로 쓰지 않고, vqascore/csd_target 같은 연속형 지표를 주 근거로 사용하는 쪽으로 방향 전환.

13. CSD Golden Set 전환 (csd_target → csd_golden)

lecture24 8카테고리 참조 이미지(카테고리당 15~24장, 총 158장)를 검증·매니페스트화하여 카테고리당 참조 1장(provisional)이던 기존 csd_target을 다중참조 평균 방식으로 전환, 기존 18개 run·420장 재채점.

  • 상관관계 강함: Pearson r=0.83, Spearman ρ=0.78 — 상대 순위는 대체로 유지.
  • 절대값은 전반적으로 하락: 420장 중 334장(80%)에서 csd_golden < csd_target, 평균 delta -0.107.
  • 카테고리별 방향·크기가 다름: Single-Character Cutout(-0.240) 크게 하락 vs Historical Figure Portrait(+0.046) 오히려 상승 — 원인 미확정(열린 질문).
  • run 간 상대 비교(TASK-F, TASK-G)는 재검토 불필요, but 카테고리 그룹 절대값 해석(TASK-I 등)은 재검토 필요.

14. 결론 & 미결 사항

확정된 결론

  • 모델 후보: flux2-klein-4b-nf4가 종합 1위(harmonic 0.653), lumina2가 복합 프롬프트 안정성 1위, pixart-sigma는 counting 약점.
  • VLM spec-item judge(Qwen2.5-VL/Gemma-3/InternVL3 3종 전부) 신뢰 불가(κ<0.6 확정) — 연속형 지표(vqascore/csd_target) 중심으로 전환.
  • 리라이팅 시스템 프롬프트를 공식 레포 구조에 맞게 재작성하면(_cn 버전) 뚜렷한 개선 — 특히 promptenhancer_cn.
  • "프롬프트가 길수록 counting이 나빠진다" 가설 기각 — 오히려 반대(단, 길이보다 디테일 보존이 실제 원인일 가능성).
  • Ideogram-4 안전필터 차단은 캡션 스키마가 아니라 캡션을 생성한 LLM/백엔드가 핵심 변수.

아직 미결 (README.md 체크리스트 마지막 항목)

  • 3단계 병행 개선 루프 진입 — pixart-sigma의 counting 약점이 judge 오탐인지 실제 모델 한계인지 이미지 직접 확인 필요 (미체크).
  • csd_golden 카테고리별 delta 방향이 갈리는 원인 조사.
  • csd_golden을 정식 채점 경로로 승격할지 여부.
  • TASK-J(스타일 프리셋 LoRA 전환 임계값) — 보류 상태.
  • Ideogram-4 텍스트 렌더링 성공 여부(원래 TASK-G 목적)는 자동 지표로 답 안 나옴 — 육안 판정 필요, 미완료.
